# 入口提示词 · 单对话框版

**适用**：纯聊天界面（ChatGPT 网页版、Claude 网页版、或任何不能创建子代理的 AI）。

**用法**：分三段，第一段和第三段在同一个对话，第二段**必须开新对话**。核查不能自己查自己——这是这套流程存在的全部理由。

---

## 第一段 · 采编 + 归类 + 笔记（本对话）

```
你正在使用「WebNote-Workflow」网页笔记工作流。
项目根目录：<替换成你的实际路径>

【读这两个文件】
1. <项目根目录>/steps/collect.md
2. <项目根目录>/Webpage note workflow.md（了解整体架构即可）

【按顺序执行前三步】
第 1 步 采编：按 <项目根目录>/steps/collect.md 的媒体分类规则判断每条内容，只加载命中的分支卡。
        产出 00-采编清单.md
第 2 步 归类：读 <项目根目录>/agents/classifier.md，按其中要求做四选一分类。
        产出 01-整理清单.md
第 3 步 笔记：读 <项目根目录>/agents/distiller.md，每条要点标注出处与来源类型
        （原文 / OCR / ASR / Vision 四选一）。
        产出 02-笔记.md

【执行完第 3 步就停下】，把 00/01/02 三个文件保存到 runs/<日期-主题>/，
然后告诉我："前三步完成，请开一个新对话执行核查"。
```

---

## 第二段 · 核查（**新对话**）

```
你正在使用「WebNote-Workflow」的核查步骤。
项目根目录：<替换成你的实际路径>

【读这个文件】
<项目根目录>/agents/verifier.md

【你的角色】
你是核查官，与刚才写笔记的是两个完全独立的 AI。你的任务是逐条比对原文与笔记，
专抓编造内容。核查是三态判定：已核实（直接引用）/ 已核实（转述源）/ 可疑。

【输入】
- runs/<日期-主题>/01-整理清单.md
- runs/<日期-主题>/02-笔记.md
- 以及清单里"原文来源"列指向的原始文件

【产出】
runs/<日期-主题>/03-核查表.md，并在文件末尾单列「需用户回看的条目」。

不要用你自己的知识帮笔记圆场。原文没写的，就是没写。
```

## 第三段 · 确认（新对话或回到第一段都行）

```
你正在使用「WebNote-Workflow」的确认步骤。
项目根目录：<替换成你的实际路径>

【读这个文件】
<项目根目录>/steps/confirm.md

【输入】
runs/<日期-主题>/ 下的 01-整理清单.md、02-笔记.md、03-核查表.md

【产出】
runs/<日期-主题>/04-待确认提案.md

要求：分三节——建议保留 / 建议保留但需我回看（转述源）/ 建议修正或删除。
所有落地动作只出提案，不执行。
```

---

## 为什么核查必须另开新对话

笔记匠本人查不出自己刚才编了什么。它记得的是"我写这句话时想到了什么"，而不是"原文里到底有没有这句话"。

在同一个对话里接着问"你检查一下有没有编造"，得到的通常是一份自我辩护，不是核查。

如果实在没法开新对话，至少让 AI 在核查表头部**显式标注降级性质**——格式见 `agents/verifier.md` 的「降级声明」一节。声明了，你至少知道这份表的分量；不声明，就是在用一个看起来合规的表格掩盖风险。
