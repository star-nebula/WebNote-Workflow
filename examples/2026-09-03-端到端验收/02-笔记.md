## p01 · Git 提交信息规范实践

**来源**：`.../webpage-1-git-convention.md`（图文剪藏）

### 核心要点

1. 提交信息分三部分：标题行（summary）、正文（body）、脚注（footer）；标题行 ≤50 字符、祈使句开头；正文解释"为什么改"而非"改了什么"；脚注放 issue 编号与 BREAKING CHANGE 标记。
   —— 出处：正文「提交信息的结构」段
2. 约定式提交格式 `<type>(<scope>): <subject>`；type 清单含 feat/fix/docs/refactor/chore/test；scope 可选，如 `feat(auth): 增加短信登录`。
   —— 出处：正文「约定式提交」段
3. 收益三点：可直接当 changelog 素材（`git log --oneline`）、便于 git bisect 判断问题提交、reviewer 能快速理解提交意图。
   —— 出处：正文「为什么值得做」段（三点 1/2/3）
4. 三大误区：只用 `-m` 省正文、多个无关改动塞进一个提交、标题写"修改了一些东西"；推荐习惯：先 `git diff` 自查，再按主题拆多个逻辑提交。
   —— 出处：正文「常见误区」段 + 「推荐习惯」句

### 为什么值得保留
一页纸讲清团队级提交规范的结构与理由，含可直接抄用的 type 清单与常见误区，适合作为团队提交规范的最小范本。

### 修订建议
值得深读 / 可作为团队规范落地参考。

## p02 · 久坐族的脊柱健康：几个被低估的细节

**来源**：`.../webpage-2-spine-health.md`（图文剪藏）

### 核心要点

1. 腰椎有向前自然弧度（前凸）；坐姿最大错误是"塌腰"（骨盆后倾→腰椎弧度压平→椎间盘后侧压力骤增）；正确坐姿是骨盆微微前倾、保持腰椎弧度，而非"挺直"。
   —— 出处：正文「腰椎的自然曲度」段
2. 椅子关键在支撑位置而非硬度：腰托顶在腰椎第 3–5 节位置（不是臀部）；坐深让大腿全落坐垫、膝弯约 90°、脚平踩地面；扶手高度让肩膀自然放松下垂。
   —— 出处：正文「椅子不是越硬越好，支撑位置才关键」段（三条）
3. 危害在"连续时间"：每 45–60 分钟起身一次（哪怕伸懒腰/走几步）显著降风险；番茄钟法适用。
   —— 出处：正文「每 45-60 分钟起来一次」段
4. 补充：屏幕顶端与视线齐平或略低；键鼠放肘部高度、前臂与地面平行；已有明显疼痛先看医生而不是先换椅子。
   —— 出处：正文「一些补充」段

### 为什么值得保留
把"腰托顶哪、坐深多少、多久起来"这类可操作细节讲清了，且纠正了"坐得越直越好"的常见误解，属可直接执行的身体健康方法。

### 修订建议
值得深读 / 可直接应用到工作习惯。

## p04 · MarkdownLint 工具使用说明 v1.4

**来源**：`.../markdownlint-manual.docx`（python-docx 提取）

### 核心要点

1. 安装：`pip install markdownlint-cli`，用 `markdownlint --version` 验证；适用于 Windows/macOS/Linux。
   —— 出处：文档「安装」段
2. 用法：单文件 `markdownlint README.md`；目录递归 `markdownlint docs/`；自动修复 `markdownlint --fix docs/`。
   —— 出处：文档「基本用法」段
3. 三条常用规则：MD001 标题层级逐级递增不许跳级；MD013 默认每行 ≤80 字符（可配置调大适配中文长句）；MD024 不允许相同内容重复标题。
   —— 出处：文档「常用规则说明」段
4. 配置：项目根放 `.markdownlint.jsonc` 自定义开关与参数；示例可关闭行长度限制并开启中文友好空格规则。
   —— 出处：文档「配置文件」段
5. FAQ：检查报告乱码→终端切 UTF-8；与 Prettier 冲突→markdownlint 只做语法规则、格式交给 Prettier。
   —— 出处：文档「常见问题」段

### 为什么值得保留

   —— 出处：帧 t=100–115s（红果热播榜界面 OCR + WPS 记录"1：剧本 直接红果 找大热门的漫剧 仿写剧本"）

   —— 出处：帧 t=125s、t=195s（WPS 提示词文档 OCR，含编剧/角色设计师/分镜师/提示词撰写师四段）
